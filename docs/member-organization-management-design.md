# 会员设置页面设计

日期：2026-10-04

状态：已按确认范围实现，自动化验证通过，真实 Logto 联调待验收
适用项目：CQAI Club Portal

## 1. 页面目标与初始配置

增加一个管理员使用的「会员设置」页面，完成三个操作：查看受管理组织的成员、配置 Logto 组织 ID、将已有 Logto 用户加入指定组织。同时接通会员申请审核：申请审核通过后，自动将申请人加入创享会员组织。当前只配置创享会员组织。

| 会员类型 | Logto 组织 ID | 初始状态 |
| --- | --- | --- |
| 创享会员 | `rar9vrcnuavh` | 预填，待连接验证 |

本页是管理员后台工具，初始管理范围是创享会员组织，不涉及普通会员的配置、列表或身份判定。后续需要管理其他组织时，可新增组织配置。

会员类型统一使用「创享会员」名称，沿用同一组织绑定。

组织 ID 来自用户提供，本稿未访问 Logto 验证组织名称、是否存在及实际成员数量。界面里的姓名和数量均为示例。

## 2. 入口与页面结构

管理员侧栏新增「会员设置」，保留现有「会员申请」入口。

建议页面地址：`/member/dashboard/admin/member-settings`。

```text
管理区
  资料管理
  活动管理
  会员申请
  会员设置  ← 新增
  …
```

页面以会员列表为主，右上角提供组织选择器和组织配置抽屉入口：

| 区域 | 内容 | 主要操作 |
| --- | --- | --- |
| 会员列表 | 当前选择组织的实际成员 | 切换组织、搜索、查看成员、添加成员 |
| 右侧组织配置抽屉 | 组织展示名称与 Logto 组织 ID | 新增、编辑、验证、保存 |

默认展示会员列表。右上角选择当前组织，点击「组织配置」从右侧打开抽屉；移动端抽屉使用全宽。组织配置未完成时，列表内的「组织配置」按钮同样打开抽屉。

## 3. 会员列表界面

### 3.1 桌面布局

```text
会员设置               当前组织：[创享会员 ▼] [组织配置]
查看创享会员组织成员，并将已有账户加入组织。

────────────────────────────────────────────────────────────
最近同步：尚未同步                      [刷新] [添加成员]

[搜索姓名 / 用户名 / 邮箱 / 手机号                  ] [搜索]

成员                     所属会员组织       加入时间       操作
────────────────────────────────────────────────────────────
张三                     创享会员           —              查看
zhangsan · z***@mail.com
用户 ID：示例用户 ID

李四                     创享会员           —              查看
lisi · 138****0000
用户 ID：示例用户 ID
────────────────────────────────────────────────────────────
共 N 位成员                   每页 20 条    [上一页] [下一页]
```

初始组织选择器只有创享会员一个选项。新增其他受管理组织后，可在这里切换；搜索条件和分页在切换时重置。

### 3.2 列表字段

| 字段 | 展示规则 |
| --- | --- |
| 成员 | 姓名；无姓名时使用用户名，仍无则显示用户 ID |
| 联系方式 | 邮箱、手机号默认脱敏；获授权的详情中可查看完整信息 |
| 用户 ID | 支持复制，供管理员准确区分同名用户 |
| 所属会员组织 | 显示当前组织名称；详情可展示该用户所属的其他受管理组织 |
| 加入时间 | 仅展示实际可获得的组织加入记录；历史数据没有记录时显示「—」 |
| 操作 | 「查看」，打开成员详情弹窗 |

成员详情弹窗展示账户信息和已配置会员组织中的成员关系。加入其他组织时，在列表选择对应组织，再从现有用户中勾选加入。成员列表支持移除：确认后移出当前组织，保留用户账号及其他组织关系。

### 3.3 列表口径

- 列表只展示当前选择组织的实际成员，按 Logto 用户 ID 去重。
- 不展示普通会员分类，也不推算未加入当前组织的账号属于哪种会员。
- 同一用户可加入多个受管理组织，并在各自列表中出现。
- 不把 Logto 租户内的全部账号直接展示为本俱乐部会员。
- 成员数量来自组织成员关系，不使用申请数量或当前页行数代替。
- 搜索、总数及分页都限定在当前组织；不能仅过滤当前已经加载的一页数据。
- 当前组织读取失败时显示重试；其他已配置组织仍可切换查看。

## 4. 添加成员弹窗

### 4.1 布局

```text
添加成员                                                   [关闭]
从现有用户中勾选成员，加入当前会员组织。

目标组织 *
[创享会员]
组织：实际读取的组织名称
组织 ID：rar9vrcnuavh

现有用户
[筛选姓名 / 用户名 / 邮箱 / 手机号 / 用户 ID      ] [筛选]

□ 全选本页可加入用户

□ 张三  · zhangsan · z***@mail.com
  用户 ID：示例 ID A                 尚未加入目标组织

✓ 李四  · lisi · 138****0000
  用户 ID：示例 ID B                 已选择

  王五  · wangwu · w***@mail.com      已在组织内

共 N 位现有用户           每页 20 位        [上一页] [下一页]
已选择 1 位用户                                  [清空选择]

[取消]                                      [加入创享会员组织]
```

### 4.2 操作规则

- 从当前组织列表点击「添加成员」，弹窗固定使用当前组织，清楚展示其名称和 ID。
- 要添加到其他受管理组织时，先关闭弹窗并切换列表组织，避免选择用户过程中改变加入目标。
- 打开弹窗即通过服务端读取 Logto 现有用户，直接展示第一页，每页 20 位；无需先输入搜索词。
- 管理员直接勾选一个或多个现有用户，第一版每次最多加入 20 人。
- 搜索框仅用于筛选现有用户；清空筛选后恢复完整的现有用户列表。
- 支持「全选本页可加入用户」；仅选择当前页可加入的账户，达到每次 20 人上限后停止继续选择并提示。
- 翻页或筛选时按用户 ID 保留已选账户，底部显示全部已选人数，并支持取消单人选择或清空选择。
- 初次加载或翻页中显示列表骨架；读取失败显示重试，保留已选账户。
- 未配置或不可用的组织不能作为可提交目标。
- 已在目标组织内的用户显示「已在组织内」，禁用勾选。
- 用户选择列表与组织成员列表分别呈现；这里展示现有账户，加入成功后才出现在目标组织成员列表中。
- 筛选无结果时提示「没有符合条件的现有用户」，提供「清除筛选」；现有用户列表本身为空时显示「暂无可选用户」。
- 本流程仅选择已有账户，不提供新建用户、手动填写成员资料或发送邀请的步骤。
- 提交前展示目标组织、已选账户姓名和用户 ID；用户选择后直接在同一个弹窗确认，无需再弹第二层确认框。
- 加入操作只增加指定会员组织成员关系，保留用户已有组织及全局角色。
- 第一版不自动修改组织角色；本页以组织成员身份管理会员范围。

### 4.3 提交反馈

| 状态 | 界面反馈 |
| --- | --- |
| 未选择用户 | 提交按钮禁用，提示「请选择用户」 |
| 提交中 | 按钮显示「正在加入…」，防止重复提交 |
| 成功 | 提示「已将 N 位用户加入创享会员组织」，刷新成员关系与列表 |
| 重复加入 | 刷新为「已在组织内」，不重复创建关系 |
| 部分失败 | 展示逐人结果，保留失败人员，提供「重试未完成成员」 |
| 请求结果不确定 | 提示「加入结果待确认」，重新读取成员关系后确认，避免直接宣告失败或成功 |
| 权限或连接失败 | 保留筛选和选择，显示可重试原因 |

## 5. 组织配置界面

### 5.1 布局

```text
会员设置

会员列表  [组织配置]
────────────────────────────────────────────────────────────
创享会员
用于展示创享会员列表，并作为管理员添加成员的目标组织。

Logto 组织 ID *
[rar9vrcnuavh                                    ] [验证组织]
待验证

验证成功后：
组织名称：Logto 实际返回的名称
组织状态：可读取
当前成员：实际读取的数量，未获取时显示「—」

[取消修改]                                           [保存配置]

[新增组织配置]
```

点击「新增组织配置」后填写「展示名称」与「Logto 组织 ID」，验证真实组织后保存。展示名称只用于本后台，不修改 Logto 中的组织名称。新增项保存后出现在会员列表的组织选择器中。

### 5.2 保存规则

| 项目 | 规则 |
| --- | --- |
| 字段标签 | 固定为「Logto 组织 ID」，避免与组织名称混淆 |
| 验证 | 服务端读取目标组织，返回真实名称，供管理员识别 |
| 保存条件 | 保存的新 ID 必须验证成功；服务端保存时再次校验 |
| 修改后状态 | 任何输入变化都清除旧验证结果，要求重新验证 |
| 重复绑定 | 同一个 Logto 组织 ID 不允许重复创建配置 |
| 保存粒度 | 每张卡片独立保存；并发编辑冲突时提示刷新，保留本次输入 |
| 数据保存位置 | 项目服务端持久化配置，浏览器只负责输入与展示 |
| 首次预填 | `rar9vrcnuavh` 只是初始值，验证并保存后才成为有效绑定 |

替换已有绑定时，在卡片内展示变更确认：

```text
你正在将创享会员组织从「原组织」改为「新组织」。
保存后，创享会员列表和添加成员操作将使用新组织。
已有成员不会自动迁移。

□ 我已核对新组织及以上影响
                                              [确认保存]
```

配置管理只绑定已有组织，不创建、删除或重命名 Logto 组织。创享会员绑定同时控制项目征集和资料中心的访问范围；替换组织后，这两项功能使用新组织的实际成员关系判断权限，已有成员不会自动迁移。

## 6. 页面状态与移动端

| 场景 | 表现 |
| --- | --- |
| 首次未验证 | 列表显示「请先验证并保存创享会员组织」，提供组织配置入口 |
| 组织为空 | 显示「该组织暂无成员」和「添加成员」按钮 |
| 搜索为空 | 显示「没有符合条件的成员」，提供清除搜索 |
| 正在读取 | 显示表格骨架或进度状态，不把数量暂时显示成 0 |
| 组织不存在 | 配置卡片显示错误；对应列表及添加操作不可用 |
| Logto 暂时不可用 | 显示重试入口；若保留旧列表，标注上次成功同步时间 |
| 管理权限不足 | 显示无权访问；服务端同时拒绝请求 |
| 会话失效 | 提示重新登录，保留可恢复的页面筛选条件 |

移动端将成员表格转换为纵向卡片，优先展示姓名、联系方式、组织标签与操作。添加弹窗使用接近全屏的布局，操作按钮固定在底部且不遮挡内容；有多个组织配置时，卡片上下排列。

沿用现有会员中心的颜色、字体、卡片、按钮和弹窗组件。创享会员使用主题色标签，组织名称以文字清楚展示。页签、选择框、验证与提交操作均支持键盘，按钮触控区域至少 44px，错误提示放在对应字段或操作附近。

## 7. 权限与现有流程衔接

### 7.1 管理权限

第一版沿用现有 `member:admin` 管理权限，控制页面访问、现有用户列表及筛选、组织配置、添加成员、申请审核和加入重试；这些接口均需在服务端验证权限。

组织加入操作由服务端持有 M2M 凭据调用 Logto Management API。目标组织必须是服务端已经保存并验证的会员绑定，不能接受客户端指定任意组织。普通用户无权通过本页面更改绑定或添加自己。

### 7.2 申请审核通过后自动加入组织

普通会员在「会员类型」的创享会员卡片点击申请按钮，打开右侧抽屉填写申请或查看已有申请状态与资料。侧边栏不再提供独立的「创享会员申请」入口；旧申请链接和重新登录返回地址会先验证当前会员身份，普通会员进入会员类型并自动打开抽屉，已是创享会员则展示会员权益，无法验证时提示重试。已是创享会员时，即使链接带有打开申请抽屉的参数，也不会展示申请抽屉。后台会员申请的审核操作保留。这里的「申请成功」指管理员审核通过并确认加入组织完成；提交申请成功仅表示进入待审核状态。

会员类型顶部展示当前身份与已开通权益。普通会员展示基础权益，并在「未开通权益」中展示创享会员的资料中心、项目征集及申请按钮；创享会员展示基础权益和创新权益，已开通的权益不再作为待申请项展示。当前仅提供普通会员与创享会员，企业会员和创始会员暂不展示。身份读取失败时显示重试，不推断为普通会员；资格以当前创享会员组织的实际成员关系为准。

```text
用户提交申请
    ↓
待审核
    ↓ 管理员点击「审核通过」
系统自动加入已配置的创享会员组织
    ↓ 重新读取并确认组织成员关系
已通过 · 已加入组织
```

申请详情的操作区设计如下：

```text
创享会员申请
申请人：张三      登录账户：zhangsan
申请状态：待审核

审核通过后将自动加入：创享会员
组织 ID：rar9vrcnuavh

审核备注（选填）
[                                                  ]

[不通过]                                       [审核通过]
```

点击「审核通过」后，按钮显示「正在通过并加入…」。系统使用申请记录中绑定的 Logto 用户 ID，复用手动添加成员的加入能力，不需要管理员再次打开添加弹窗选人。

| 状态 | 管理员页面 | 申请人页面 |
| --- | --- | --- |
| 待审核 | 显示审核操作 | 「申请已提交，等待审核」 |
| 审核通过，正在加入 | 「正在加入创享会员组织…」 | 「审核已通过，正在开通会员资格」 |
| 已确认加入 | 「已通过 · 已加入组织」；提供「查看会员」入口 | 「申请已通过，已成为创享会员」 |
| 审核通过，加入失败 | 「加入组织失败」及「重试加入」按钮 | 「审核已通过，会员资格开通暂未完成，请联系管理员」 |
| 加入结果待确认 | 「正在确认加入结果」；提供重新确认入口 | 「审核已通过，正在确认会员资格」 |
| 审核未通过 | 显示审核结果与备注 | 「申请未通过」及面向申请人的审核说明 |

关键规则：

- 目标组织统一读取「会员设置」中创享会员的有效配置，初始 ID 为 `rar9vrcnuavh`。
- 配置缺失、目标组织不可用或申请未绑定可验证账号时，禁用审核通过并提示原因；历史申请不能通过手机号自动认领账号。
- 执行审核时记录目标组织 ID、申请人账号、审核人和时间。失败重试使用该次审核记录的目标组织；配置已变更时提示管理员核对后重新选择目标，避免静默加入另一组织。
- 审核结果与组织加入结果分别记录；只有真实成员关系确认后，才显示「已成为创享会员」。
- 审核已通过但加入失败时，保留审核结果，重试只执行加入及确认，不要求重复审核。
- 如果申请人已在目标组织内，确认现有成员关系即可完成流程；重复点击或并发请求不能重复处理申请。
- 自动加入成功后，申请详情、申请人页面与会员列表以同一组织成员关系展示状态。
- 手动添加现有用户仍可独立使用，不强制要求该用户先提交申请。

### 7.3 数据权限衔接

会员中心的项目征集、资料中心入口及项目征集概览快捷入口向所有登录会员显示。普通会员进入这两个页面后显示「需要申请创享会员才能查看」及申请按钮，不展示资料内容、项目记录或提交表单；创享会员组织的实际成员可正常查看资料、提交项目和查看征集记录。

服务端每次请求实时校验 Logto 成员关系，保护资料列表及图片、项目列表、详情、封面、创建和修改，也保护旧的项目提交接口。审核已通过、曾加入组织、其他组织成员或客户端传入的会员字段均不能替代实际成员关系；移出组织后，后续请求立即拒绝。组织配置未完成或 Logto 无法验证时不返回业务内容，提示重试。

后台资料管理、资料预览和项目审核仍沿用各自管理员权限，不要求管理员同时加入创享会员组织。资料管理预览使用独立的管理员图片接口。

## 8. 第一版验收要点

- 管理员能打开会员设置，普通用户不能访问页面及对应接口。
- 创享会员组织 ID 预填为 `rar9vrcnuavh`，读取真实组织信息后保存。
- 页面只提供管理员的组织成员管理，不出现普通会员分类或配置。
- 初始只展示创享会员组织；新增受管理组织后可切换列表，各组织独立搜索和分页。
- 打开添加成员弹窗即显示现有用户，管理员可直接勾选并加入当前组织。
- 用户列表支持分页、可选筛选、全选本页及跨页保留选择；已加入目标组织的账户不可重复勾选。
- 添加完成后重新读取 Logto 成员关系，列表、统计和详情一致。
- 申请经管理员审核通过后自动加入创享会员组织，无需再次手动选人。
